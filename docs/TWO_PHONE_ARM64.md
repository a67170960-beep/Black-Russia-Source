# Запуск на двух ARM64-телефонах без VPS

## Роли

- Телефон 1: Termux и сервер.
- Телефон 2: Android-клиент/лаунчер.
- Интернет не нужен: подключи телефон 2 к хотспоту телефона 1 или оба телефона к одной Wi-Fi-сети.

## Телефон 1 — сервер

Узнай адрес телефона в локальной сети:

    ip -4 addr

Обычно при хотспоте адрес телефона-раздатчика похож на 192.168.43.1, но используй фактический адрес из команды.

Не используй официальный Linux x86-релиз open.mp на ARM64: архитектуры не совпадают. Нужен сервер, собранный под aarch64. Сборка из исходников может занять много времени и потребовать несколько гигабайт свободного места.

В Termux для подготовки окружения:

    pkg update -y
    pkg install -y git clang cmake ninja tmux proot-distro
    termux-wake-lock

Если сборка требует glibc, используй Debian:

    proot-distro install debian
    proot-distro login debian
    apt update
    apt install -y git clang cmake ninja-build build-essential

Конфиг сервера уже слушает 0.0.0.0:7777, то есть принимает подключения из локальной сети. После запуска проверь:

    ss -lun | grep 7777

## Телефон 2 — клиент

Обычный скачанный APK не подойдёт: в исходнике адрес старого сервера. Сначала нужно собрать APK из форка, указав LAN-IP телефона 1 в CNetwork.cpp.

Для примера, если телефон 1 имеет адрес 192.168.43.1:

    CSetServer::create("192.168.43.1", 404, 12, 7777, false)

404 — сумма октетов IP, 12 — длина строки IP. Обе записи серверов в CNetwork.cpp должны указывать на телефон 1.

После изменения нужно собрать JNI через Android NDK, заменить app/jniLibs/armeabi-v7a/libsamp.so и собрать APK. APK устанавливается на телефон 2.

## Реальное ограничение

Даже после сборки ARM64 open.mp текущий Android-клиент может не пройти handshake: он использует NETGAME_VERSION 4057, AUTH_BS и собственные RPC. Если сервер не видит подключение, это несовместимость протокола, а не проблема IP или Termux.

Начинай с проверки: сервер слушает UDP 7777, затем клиент пытается подключиться с телефона 2.
